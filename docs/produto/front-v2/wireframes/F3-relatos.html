Notas

  1. Seletor de tipo (radiogroup): Relatar problema (bug.yml) marca Incluir diagnóstico técnico local por padrão; Sugerir ideia (ideia.yml) e Propor Provedor ou modelo (provedor-modelo.yml) desmarcam automaticamente.
  2. Detector local de segredos: regex /token|chave|\bkey\b/i no Título ou Descrição exibe alerta não intrusivo (role="alert") sem roubar o foco do usuário durante a digitação.
  3. Allowlist estrita (diagnostic.get): coleta apenas versão, SO, GPU/encoder, Motor, Provedor, versão da Tarefa/hash do prompt, contexto efetivo e últimas ~200 linhas limpas de erro. Nota: aguarda correção da etapa fixa "componente" no Rust (lacuna #12 da consolidação).
  4. Sonda de hardware (transcription.hardware.diagnostic): exibe GPU, driver, CT2, modelo, escolha verificada, lote seguro e VRAM livre em <details>; botão anexa resumo ao texto do diagnóstico.
  5. Regra obrigatória de 2 passos (ADR-0006): os botões Copiar texto, Exportar diagnóstico (.txt) e Abrir no GitHub não existem no DOM antes do clique em Revisar relato antes de enviar.
  6. Segurança privada: link externo para SECURITY.md via openUrl.
  7. Pré-visualização editável: o usuário pode editar ou apagar qualquer linha do diagnóstico antes de copiar, salvar ou abrir no GitHub.
  8. Exportação .txt: abre diálogo nativo save e chama diagnostic.export { path, text } enviando exatamente o texto editado pelo usuário.
  9. Abrir no GitHub (openUrl): pré-preenche template, título e corpo em issues/new.
  10. Limite de 8.000 bytes na URL: se issueUrl(fullText) exceder 8.000 bytes UTF-8, copia automaticamente o diagnóstico para a área de transferência, preenche a URL com a descrição + aviso "Diagnóstico copiado — cole aqui" e notifica via role="status". Se ainda passar de 8.000 bytes, orienta usar Copiar texto completo.
